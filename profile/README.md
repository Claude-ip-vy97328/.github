<p>把住宅 IP 当成一台设备来看，它其实有一份参数表：出口归属、会话粘性、带宽、丢包、计费口径，每一项都有明确的取值范围和适用场景。多数人下单时只问「多少钱一条」，结果拿到手才发现粘性时长不够、并发卡在二十个连接上。这篇按参数分组说明，每条给出含义、常见取值、怎么验证、以及取错会怎样，可以当作选型时的对照清单。</p>

<h2>一、这份说明书怎么读</h2>
<h3>先确定你的场景类型</h3>
<p>跨境店铺多号运营属于「低频在线、长时间挂机、要求地址稳定」的类型，和抓取类任务正好相反。抓取看重并发和轮换，运营看重粘性和独占。同一份参数表，两类场景的重点不同，先把自己的类型定下来，再挑参数。</p>
<h3>参数之间的耦合</h3>
<p>粘性时长、并发数、带宽三者会互相挤压。粘性越长，同一地址上的连接越集中；并发越多，带宽占用越高；带宽不够时，表现为超时而不是变慢。所以看参数不能单看一项，要看组合是否匹配你的实际负载。</p>

<h2>二、出口类参数：归属、类型、上游</h2>
<p>出口类参数决定「这个地址在站点眼里是什么身份」，是最不该妥协的一组。下表列出四个核心项和验证方式，取值仅供参考。</p>
<table><thead><tr><th>参数</th><th>含义</th><th>常见取值</th><th>验证方式</th></tr></thead><tbody><tr><td>ASN 归属</td><td>地址所属自治系统</td><td>当地运营商 ASN</td><td>公开 IP 信息库查询</td></tr><tr><td>IP 类型</td><td>住宅、机房或移动</td><td>residential</td><td>同上，看类型字段</td></tr><tr><td>上游数量</td><td>该线路挂几家运营商</td><td>单上游或双上游</td><td>看路由第二跳网关</td></tr><tr><td>地理精度</td><td>城市与邮编是否准确</td><td>城市级准确</td><td>与订单地址核对</td></tr></tbody></table>
<h3>ASN 为什么重要</h3>
<p>站点判断一个地址是否像真实用户，看的往往不是城市而是 ASN。云厂商的 ASN 下即使标着住宅，也容易被归入可疑类别。下单前让对方给出 ASN 编号，自己查一遍，比看宣传语可靠。</p>
<h3>上游数量怎么看</h3>
<p>双上游意味着两条出口路径。验证方式是从你的机器做一次路由追踪，看第二跳是否出现两个不同运营商的网关。只在说明里写双 ISP、追踪结果只有一条路径的，按单上游计。</p>

<h2>三、会话类参数：粘性、并发、切换</h2>
<img src="/tp.png" alt="住宅IP出口参数面板中的ASN与归属字段">
<h3>粘性时长</h3>
<p>指同一出口地址能被占用的最长时间。运营场景建议不低于二十四小时，最好能做到按周或按月固定。粘性不足的表现是每天登录地址都在变，站点侧看起来像频繁更换网络，验证频率上升。</p>
<h3>并发连接数</h3>
<p>单条出口允许的同时连接数。一个浏览器环境正常浏览时可能占用十几个连接，页面元素多时更高。经验上单环境预留三十个连接比较稳妥，五个环境同时在线就要一百五十个。这一项如果卡在五十，多开就会出现资源加载失败。</p>
<h3>切换策略</h3>
<p>指异常时的处理方式：自动切到备用上游、还是直接断开重拨。前者对外地址不变，后者会变。采购时明确要求「优先切换、避免重拨」，这一条写进订单备注，能减少很多夜间的意外跳变。</p>

<h2>四、线路类参数：带宽、延迟、丢包</h2>
<h3>带宽</h3>
<p>单条出口通常给到二十兆到一百兆，运营场景很少跑满，但要注意上行。多环境同时上传图片或提交表单时，上行先满。经验值：单环境峰值上行一至两兆。</p>
<h3>延迟与抖动</h3>
<p>延迟看平均值，抖动看波动范围。平均两百毫秒、波动二十毫秒，比平均一百二十毫秒、波动一百五十毫秒的体验更稳。让服务商提供一段二十四小时探测记录，比自己测十分钟准。</p>
<h3>丢包</h3>
<p>长期挂机最怕的不是延迟高，而是间歇性丢包。阈值可以设在百分之一：连续十分钟丢包超过百分之一，就该记录一次异常。丢包往往和上游拥塞有关，双上游配置能缓解但不能消除。</p>

<h2>五、计费类参数：按条、按量、按并发</h2>
<p>三种口径对应不同负载形态，选错会让成本翻倍。下表把适用场景和注意点列出来，价格区间仅供参考。</p>

<h3>混合口径更实际</h3>
<p>核心账号包月，临时任务用按量，是很多团队的实际做法。采购时问清能否两种口径共用同一个账号体系，否则要维护两套后台和两套账单，管理成本会吃掉省下的钱。</p>

<h2>常见问答</h2>
<h3>粘性时长写着二十四小时，够用吗？</h3>
<p>答：对跨境店铺运营偏紧。二十四小时意味着每天地址可能变一次，长期下来登录历史会显得不稳定。建议至少按周固定，能按月更好，具体能谈到什么程度取决于服务商资源。</p>
<h3>并发连接数怎么估才准？</h3>
<p>答：开一个环境，用开发者工具看峰值连接数，再乘以同时在线环境数，留三成余量。这个数字比服务商给的标称值更贴合实际，因为不同页面的资源数量差别很大。</p>
<h3>延迟高但很稳，需要换吗？</h3>
<p>答：不必。运营场景对绝对延迟不敏感，对稳定性敏感。只要页面能在可接受时间内打开、不掉线，延迟两百毫秒以内都可以接受。换来换去反而破坏地址稳定性。</p>
<h3>参数表里没写的项目要不要问？</h3>
<p>答：要。常被省略的两项是 IP 的历史使用情况和更换政策。前者影响初始风险，后者影响长期成本。这两项问清楚，比多比较两家的单价更有价值。</p>
